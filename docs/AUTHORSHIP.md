# Authorship

Early commits in this project's private development history recorded the
user's git identity in the author field. Those changes were machine-authored — written by assistant
instances under the user's direction. No git user was configured in any scope,
so that identity was supplied per command.

Later commits in that history name the assistant in the author field, and an `Approved-by` trailer
names the user, so what made a change and who accepted it are two separate
recorded facts rather than one conflated one.

The earlier commits are not rewritten. Corrections to any EMET record are made by
adding — a superseding entry, a marker, a written disposition — never by removing
or editing what is already there. A history rewritten to read correctly destroys
the retained record in order to do it. This file is the addition.

This matters because the charter states that records are attributable. An author
field naming a person for machine-made changes is not attributable evidence, and
git was the one store in this system with no source-attribution mechanism: memory
entries carry a host tag and an assertion origin, document writes carry a host tag
that is never a person, transcripts carry a session id.
